# Cybersecurity_Testing_Projects
Writeup for Cybersecurity Test Project

该部分的内容主要是自己的安全测试实践

采用的过程记录结构参考了ATT&CK和Unified Kill Chain(UKC)的结构, 尝试使用类似的结构建立自己的独立渗透测试与网络安全测试的框架

在整个测试过程中, 最重要的地方在于构建一套自己的测试框架的同时, 保持对于信息收集, 身份验证信任模型的思考. 多数项目中的漏洞本身就是以来信息收集发现的, 信息收集不仅仅是作为第一步的执行环节, 还在后续环节中持续出现. 如果说渗透测试实在浴缸里游戏, 信息收集就像是浴缸里的水一样

如果出现了问题与停顿, 或者测试困境, 停下来, 深呼吸, 放松, 再次信息收集

没有绝对安全的操作系统, 测试目标是基于需求与业务构建的计算体系, 它们需要通过输出信息建立信任, 展示技术和提供服务, 信息收集就是在利用这些信息, 身份验证与信任模型则是通过滥用相关的信任完成安全测试

其次就是身份验证与信任模型, 身份验证, 授权与信任关系贯穿了Web, Cloud, API, AD以及OS, 如果你测试时, 第一件事情想的就是信息收集和寻找漏洞, 没有找到能够直接利用的漏洞的时候, 不代表测试就要停止了, 想想能否尝试利用身份验证与信任模型的思路进行测试, 从信任关系中寻找能够可被滥用的访问路径, 例如AD Tesing中的lateral movement的PTH, PTK, PTT; CLoud Testing中的接管, 逃逸, 污点横向等等, 它们在依靠着身份验证, 授权与信任关系保证业务的运行
